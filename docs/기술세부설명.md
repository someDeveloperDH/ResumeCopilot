## yaml 규약

기존 stage별 `config.yaml`은 학습용 설정입니다. 모델 학습, batch size, epoch, learning rate, train/test csv 경로는 계속 기존 yaml에서 관리합니다.

CLI 실행용 설정은 새 파일인 `cli/config.yaml`로 분리했습니다.

```yaml
runtime:
  provider: "ollama"
  base_url: "http://localhost:11434"
  model: "exaone3.5:7.8b"
  temperature: 0.2
  max_tokens: 900
  timeout_seconds: 120
  allow_rule_fallback: true

input:
  seed_threshold_chars: 30
  short_threshold_chars: 120
  long_threshold_chars: 500
  min_dump_chars: 10

interviewer:
  max_followup_questions: 1
  retry_delta_threshold: 0.1
  max_retry_per_question: 1
```

이 구조는 팀 규약을 깨지 않습니다. 학습 설정은 기존 stage yaml에 두고, CLI 런타임 설정만 `cli/config.yaml`에서 관리합니다.

## 로컬 LLM 구조

CLI 실행은 로컬 Ollama의 EXAONE 모델을 사용합니다.

```text
CLI
→ cli/config.yaml 읽기
→ Ollama API 호출
→ exaone3.5:7.8b 응답
→ Rule 검증/저장 로직과 결합
```

`cli/models.py`는 기존 Unsloth/Qwen 로딩 함수를 유지하면서, Unsloth가 없는 Mac 로컬에서도 import가 깨지지 않도록 optional import로 분리했습니다. CLI용 로컬 LLM 호출은 `ollama_chat()`에서 담당합니다.

## Rule + LLM Hybrid

모든 판단을 LLM에 맡기지 않습니다. M5 Mac 로컬 실행 비용을 줄이기 위해 rule 기반 검증과 LLM 작업을 분리합니다.

Rule 기반:

```text
입력 길이 검사
없음/모름/n 감지
숫자/%, 시간 표현 탐지
기술 키워드 탐지
준비도 지도 계산
retry delta 판단
fallback 점수 계산
```

LLM 기반:

```text
자유 입력 구조화
STAR 추출
부족한 핵심 질문 생성
최종 문단 rewrite
긴 답변 보존 rewrite
개선 요약 생성
```

Ollama 호출이 실패하면 `allow_rule_fallback: true` 설정에 따라 rule 기반 흐름으로 계속 진행합니다.

## Structured Extraction

첫 번째 LLM 호출은 자유 입력을 구조화하는 역할입니다.

출력 목표:

```json
{
  "input_type": "seed|short_dump|normal_answer|long_answer|no_experience",
  "core_experience": "핵심 경험 한 줄",
  "star": {
    "situation": "상황",
    "task": "과제/역할",
    "action": "행동",
    "result": "결과"
  },
  "tools": ["사용자가 언급한 도구만"],
  "metrics": ["사용자가 언급한 수치만"],
  "missing_fields": ["부족한 항목"],
  "followup_question": "부족한 핵심 하나만 묻는 질문",
  "improvement_summary": ["개선 요약 1", "개선 요약 2", "개선 요약 3"],
  "reuse_angles": ["문제해결", "협업", "주도성"]
}
```

중요한 원칙:

```text
사용자가 말하지 않은 도구, 수치, 성과는 생성하지 않는다.
부족한 질문은 1개만 만든다.
긴 답변은 원문 보존 rewrite 대상으로 분류한다.
```

## Rewrite Track

Track A:

```text
사용자가 의미 있는 경험을 제공한 경우
→ 제공된 사실만 STAR 흐름으로 통합
→ 언급된 도구/수치만 반영
```

Track B:

```text
사용자가 경험 없음/모름을 입력한 경우
→ 없는 경험, 수치, 키워드를 만들지 않음
→ 원문 또는 소재를 문장 clarity/tone 중심으로만 정리
```

긴 답변은 Preserve Mode로 처리합니다.

```text
문장 순서와 핵심 표현을 최대한 유지
중복 설명 제거
문제-행동-결과 흐름 정리
자동 목표 길이 적용
개선 요약 3줄 생성
원문과 개선본 모두 저장
```

## Retry State Machine

재작성 후 score delta가 낮으면 retry UI를 1회만 제공합니다.

```text
rewrite 완료
→ score_before / score_after 계산
→ delta 확인
→ delta가 threshold 미만이면 선택지 표시
   [y] 그냥 수락
   [r] 한 번만 보충
   [s] 원문 저장
→ retry는 문항당 최대 1회
```

현재 fallback 점수는 0~100 스케일이므로 `retry_delta_threshold: 0.1`은 10점 개선 기준으로 해석합니다.

  "tools": ["SQL", "Pandas"],
  "metrics": ["2시간에서 10분"],

## 자소서 준비도 지도

`cli/readiness.py`에서 저장된 카드들을 기반으로 계산합니다.

지표:

```text
경험 다양성: 저장 카드의 competency 분포
정량 성과: metrics가 있는 카드 비율
기술 키워드: tools가 있는 카드 비율
STAR 구조: S/T/A/R 채움 정도
직무 연관성: 카드 after_score 평균
```

CLI 시작 시 현재 상태를 보여주고, 저장 후 변화량을 보여줍니다.

## 소재 고갈 방지

`cli/memory.py`는 두 가지 역할을 합니다.

```text
1. 기억 탐색기
   없음/모름/n 입력 시 작은 기억 단서 선택지를 보여줌

2. 기존 카드 재활용
   오늘 질문과 저장 카드의 토큰 겹침을 기준으로 재활용 후보를 추천
```

현재는 가벼운 rule 기반 검색입니다. 추후 KR-SBERT embedding을 붙이면 semantic search로 고도화할 수 있습니다.

## 테스트 방법

기본 문법 확인:

```bash
python -m py_compile cli/main.py cli/models.py cli/session.py cli/storage.py cli/coach.py cli/readiness.py cli/memory.py
```

히스토리 확인:

```bash
python cli/main.py --history
```

로컬 실행:

```bash
ollama serve
ollama pull exaone3.5:7.8b
python cli/main.py
```

Ollama가 실행 중이 아니면 `cli/config.yaml`의 `allow_rule_fallback: true`에 따라 rule 기반 fallback으로 흐름을 확인할 수 있습니다.

테스트 중 발견하고 반영한 수정:

```text
1. exaone3.5:7.8b는 Ollama에서 chat capability가 아니라 completion capability로 노출됨
   → /api/chat 대신 /api/generate를 사용하도록 수정

2. rewrite 프롬프트가 길면 timeout 가능성이 있음
   → rewrite 프롬프트와 max_tokens를 줄이고 timeout_seconds를 180초로 조정

3. EXAONE 응답의 "최종 문단", "개선 요약" 표기 변형 처리 필요
   → split_rewrite_response()에서 공백/마크다운 변형을 파싱하도록 보완
```
